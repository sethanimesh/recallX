# Durable document imports

Run the API and a Celery worker against the same `RECALLX_DB_PATH` and `RECALLX_DATA_DIR`. Queue messages carry job IDs; originals, checkpoints, candidates, review drafts and the dispatch outbox live on disk/SQLite. The API's recovery loop and the periodic worker dispatcher can recover queued work after Redis restarts. The API requires a paired device token for every ingestion route, including source previews.

## Native Mac OCR

Use Python 3.11 arm64 in a separate `.venv-ocr`; install `requirements-ocr.lock.txt` for the verified runtime. Run `scripts/prepare_ocr_models.py` inside that environment to fetch the exact revisions in `ocr-models.json`. The default paths are `backend/models/ocr/PP-DocLayoutV3` and `backend/models/ocr/PaddleOCR-VL-1.6`. Overrides: `RECALLX_OCR_PYTHON`, `RECALLX_OCR_LAYOUT_DIR`, `RECALLX_OCR_MODEL_DIR` and `RECALLX_OCR_MODEL_REVISION`.

The default is full PaddleOCR layout analysis and reading order on CPU with local MLX VLM recognition. Each page uses separate processes under `local_runtime.inference_lease`, batch size 1, a 300-second page deadline and process teardown. Do not keep a grading model or another large local model resident while OCR runs. `RECALLX_OCR_ACCELERATOR=cpu` selects full CPU recognition for diagnostics. Its M2 Pro 16 GB smoke peaked at roughly 9.76 GB process RSS and recognized two English sentences exactly; this is a small compatibility result, not a broad multilingual quality claim.

Install `requirements-mlx.lock.txt` in `.venv-mlx`; it pins the verified MLX-VLM 0.7.3 runtime. The worker creates an owned loopback MLX service inside the shared lease for each page, runs full Paddle layout plus MLX recognition, and terminates the service before releasing memory. A 360-second service lifetime also limits orphaned children. MLX uses a 6 GiB allocator guideline and a 256 MiB idle cache; the guideline is not a hard process RSS cap. `RECALLX_MLX_PYTHON` can select a different isolated interpreter. Standard Docker GPU deployment is not the Mac runtime.

The real CPU-layout/MLX-recognition smoke passed on this M2 Pro: exact two-sentence recognition, valid boxes, 22.719 seconds including cold startup and queue time, and 2,243,002,368 bytes of sampled owned-process RSS. RSS can double-count shared pages and excludes separately accounted Metal allocations, so it is not total unified-memory use or a direct memory comparison with CPU execution. The earlier MLX-VLM 0.3.11 compatibility failure is preserved alongside the successful 0.7.3 result.

`RECALLX_MLX_URL` can point to a separately managed loopback service for diagnostics, but that service must unload models between workloads itself. Prefer the owned service for memory coordination. CPU and MLX compatibility results remain separate artifacts.

## Dispatch and limits

Start Celery with `-A ingestion.tasks:celery_app worker --pool=solo --concurrency=1`; use the project's supervisor for Redis and API startup. Beat can call `recallx.ingestion.recover` every 30 seconds. Worker leases fence stale deliveries, page/chunk commits are atomic, and terminal validation failures require correction before retry. Transient extraction failures retry at most three times with 1/2-second backoff. Cancellation prevents later stage writes; a currently running page may finish before its subprocess exits.

Retry/cancel requests carry a durable `operation_id` and the job's `control_revision` as `expected_revision`. Replaying an acknowledged cancellation cannot cancel a later resumed job. Review drafts use a separate `draft_revision` returned as `revision` by the draft endpoint; saves carry their own operation UUID and expected draft revision. Stale saves are rejected, and approval can require `expected_draft_revision` so another device's newer edits cannot be silently bypassed. UUID receipts return the original result after lost acknowledgements without repeating invalidation, dispatch or approval.

Uploads are at most 20 MB, 100 PDF pages, or 20 million source-image pixels. Pasted text has a separate 100,000-character contract. Encrypted/corrupt PDFs are rejected. Native PDF text is used page by page when suitable; other pages go through full OCR. Source coordinates are displayed-page points for PDFs and EXIF-normalized original-image pixels for images; plain text has no fabricated geometry. Crop offsets are translated back to original-image coordinates. Raw parser results remain in page stages. Each human source correction stores immutable before/after text and revisions, with its UUID operation receipt committed atomically with candidate invalidation and dispatch. Retry the same `operation_id`, `expected_revision` and `text` after a lost acknowledgement; stale new corrections are rejected. Candidate citations identify the input passage, and are not asserted to be word-level semantic alignments.

Draft generation defaults to the existing configured provider chain. `RECALLX_DRAFT_PROVIDER=ollama` requires loopback Ollama. All local Ollama paths, including configured drafts, lookup, mnemonic and story generation, take the shared memory lease and request immediate model unloading. Lease acquisition is cancelable without blocking the API event loop. General-document and vocabulary-MCQ modes are explicit. Definitions are separated from legacy appended etymology; reference rubrics remain unapproved drafts. Accept/reject/edit/tag drafts survive reload locally and on the server. Acceptance atomically creates or reuses a sense, its source links, draft rubric, and two initial scheduling identities. Stable approval IDs prevent duplicate commits.

`GET /ingestion/items/{item_id}/sources` exposes accepted source hashes, passage citations, crop metadata and cited page geometry. Original and preview links require the paired token; local storage paths are not exposed. Word detail keeps this source history available after the import has been accepted.

## Validation

`python -m pytest tests/test_ingestion.py` uses controlled generation and real native PDF fixtures; it checks multipart bytes, page routing, crop/rotation coordinates, auth, cancellation, retries, worker recovery and atomic/idempotent acceptance. `python scripts/smoke_ocr.py` explicitly loads real pinned OCR models and writes its result to `evidence/ocr/smoke.json`; it fails when models or parsing are unavailable. Latency includes waiting for the shared inference lease and is labeled accordingly.

`python scripts/smoke_ocr.py --accelerator mlx` checks the same full pipeline using the owned MLX recognition service and records `evidence/ocr/smoke-mlx.json`. Its sampler reports summed RSS for the smoke process and owned children; shared pages may be counted more than once. Sandboxed sessions that cannot access Metal need normal host execution to run this test.

`python scripts/smoke_ingestion_queue.py` starts an owned temporary loopback Redis and real Celery worker against an isolated database. Its deterministic drafting fixture avoids external providers while the parser handles real PDF bytes. It checks broker-outage persistence, abruptly stops its worker after a page checkpoint, lets a shortened test lease expire, and verifies replacement-worker recovery and duplicate-delivery idempotency. It cleans up its own processes and records `evidence/ingestion/redis-smoke.json`; this is a queue reliability result, not a model-quality result.
